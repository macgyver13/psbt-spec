PSBT Validity Specification

Generated from the declarative rule graph in rust/src/spec.rs. Each rule names the function that enforces it, and a failing PSBT reports the rule's ID as its error code. Do not edit this file by hand.

A PSBT is valid if and only if every rule below holds. Rules run in order and stop at the first failure. Rules prefixed with a condition apply only when it holds; rules marked From BIP-n apply only in validators that implement that BIP. Signer, Input Finalizer and Extractor rules are checks those roles make on a PSBT that is already valid, before signing, finalizing or extracting it. Combiner rules compare the valid PSBTs a Combiner was given with the valid PSBT it produced.

Definitions

Map
A sequence of key-value records ending at a 0x00 separator. A PSBT holds one global map, then one map per input, then one map per output.
Key data
The bytes of a key after its compact size key type.
Unsigned transaction
The transaction a PSBTv0 carries in PSBT_GLOBAL_UNSIGNED_TX, in non-witness serialization.
Lock time type
Height-based (below 500,000,000) or time-based (at or above it). BIP-370 picks the type every input that requires one supports, preferring height on a tie.
Witness program
A scriptPubKey of a version opcode (OP_0 or OP_1 through OP_16) followed by a single 2 to 40 byte push.
Silent payment output
An output with PSBT_OUT_SP_V0_INFO. Its first 33 bytes are the scan key and its last 33 the spend key.
Eligible input
An input whose spent scriptPubKey (from PSBT_IN_WITNESS_UTXO, else PSBT_IN_NON_WITNESS_UTXO) is P2PKH, P2WPKH, P2SH-P2WPKH or P2TR, except a P2TR output that PSBT_IN_TAP_INTERNAL_KEY and PSBT_IN_TAP_MERKLE_ROOT, or a final script path witness, show has the BIP-341 NUMS internal key. A P2SH input with no redeemScript is an error.
Public key
Of an eligible input: the P2TR output key, or else the first 33-byte key from a PSBT_IN_BIP32_DERIVATION, or from the final witness or scriptSig, that the spent scriptPubKey commits to.
